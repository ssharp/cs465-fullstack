# cs465-fullstack
CS-465 Full Stack Development with MEAN

This project combines multiple frontend approaches, including traditional Express‑rendered HTML, dynamic JavaScript, and a modern Angular single‑page application (SPA) for administrative functionality. The customer‑facing side uses Express templates to deliver server‑rendered pages, which keeps the experience simple and fast for general users. In contrast, the admin SPA provides a richer, more interactive interface that updates content without reloading the page, improving workflow efficiency for trip management. While Express HTML relies on server‑side rendering, the SPA relies on client‑side rendering, routing, and component‑based UI logic. JavaScript is used across both environments, but in the SPA it plays a more significant role in handling state, routing, and API communication. The backend uses a NoSQL MongoDB database because its flexible document structure aligns well with JSON‑based trip data, supports rapid iteration, and scales easily for applications with evolving schemas.

Continuing, JSON differs from JavaScript because JSON is strictly a data format, while JavaScript is a programming language capable of logic, control flow, and computation. JSON acts as the bridge between the frontend and backend, allowing the SPA and Express routes to send and receive structured data through API endpoints. Throughout development, several sections of the codebase were refactored to improve clarity and reduce duplication, such as consolidating repeated API calls into shared Angular services and reorganizing Express routes for cleaner separation of concerns. These refactors improved maintainability and reduced the likelihood of bugs caused by repeated logic. The SPA’s reusable UI components—such as trip forms, list displays, and navigation elements—allowed consistent styling and behavior across multiple admin pages. Reusability also made future updates easier, since changes to a component automatically propagate wherever that component is used.

Testing the Travlr application required verifying both request and retrieval methods across multiple API endpoints, ensuring that GET, POST, and PUT operations behaved correctly. Each endpoint needed to be tested for proper input validation, correct response formatting, and appropriate error handling. Security layers added complexity, especially for admin authentication, because protected routes required token verification and rejection of unauthorized requests. Understanding methods and endpoints meant recognizing how each route mapped to a specific backend controller function and how the frontend consumed those routes through HTTP requests. Security required ensuring that login credentials were handled safely, tokens were validated, and sensitive admin operations were never exposed to unauthenticated users. Together, these testing practices ensured that the full stack application operated reliably, securely, and consistently across both customer‑facing and administrative interfaces.
